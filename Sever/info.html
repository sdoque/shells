mbaigo Raspberry Pi executables

This directory hosts pre-built linux/arm64 binaries of the mbaigo systems, ready to run on a Raspberry Pi 4 or 5 (64-bit OS). Each system lives in its own subdirectory containing the executable (<system>_rpi64) and a README.md.

Three companion shell scripts make it easy to download, start, and stop a set of systems on a Pi. They all read a plain-text systems.txt that lists the system names you want to work with, one per line; blank lines and lines beginning with # are ignored.

About the systems

To learn what each system does, how it is configured, and how it fits into an Arrowhead local cloud, see the source repository on GitHub:

https://github.com/sdoque/systems/tree/dev

Note: the link above points to the dev branch, not to main. The binaries hosted here are built from dev, so that branch is the authoritative reference for the current behaviour of the executables.

Getting the scripts

From the terminal in the directory where you want to keep your systems, fetch the three shell scripts and a starter systems.txt from this server:

BASE=https://staff.www.ltu.se/~deventer/rpiExec
curl -fsSL -O $BASE/downloader.sh
curl -fsSL -O $BASE/start_systems.sh
curl -fsSL -O $BASE/stop_systems.sh
curl -fsSL -O $BASE/systems.txt
chmod +x downloader.sh start_systems.sh stop_systems.sh

Edit systems.txt to keep only the systems you actually want on this Pi (one per line; blanks and lines starting with # are ignored), then proceed with the steps below.

1. downloader.sh — fetch the binaries

Reads systems.txt and, for each listed system, downloads <system>/<system>_rpi64 and <system>/README.md from this server into the matching local subdirectory. The executable is marked executable after download. Download failures are logged to download_errors.log.

chmod +x downloader.sh
./downloader.sh                 # uses ./systems.txt by default
./downloader.sh my_systems.txt  # or specify a different list

To pull from a different host (e.g. a mirror or a local server):

REPO_BASE=https://example.org/rpiExec ./downloader.sh systems.txt

2. start_systems.sh — launch everything

Kills any pre-existing systems tmux session, then starts each listed system in its own pane inside a new session. Panes are tiled, up to MAX_PANES per window (default 4), with additional windows created as needed. The script attaches your terminal to the session when it is done.

./start_systems.sh                   # uses ./systems.txt
./start_systems.sh my_systems.txt    # or a custom list
MAX_PANES=6 ./start_systems.sh       # more panes per window

Requires tmux.

3. stop_systems.sh — shut everything down

Sends Ctrl+C to every pane in the systems tmux session, waits 3 seconds for graceful shutdown, then kills the session.

./stop_systems.sh

Typical workflow

# once
./downloader.sh systems.txt

# each working session
./start_systems.sh systems.txt   # launch everything
# ... work ...
./stop_systems.sh                # clean shutdown
